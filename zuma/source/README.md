# ZUMA launch site (Tricolor)

The ZUMA shop, built on the **ZUMA brand guide**. Every research area is three tones of one colour in horizontal bands
(light: who; bright: the compound; deep: the research-use rules). Everything else, including every button, is in the
house colours (ink, paper, sand, white). Two rules make the page easy to use:

- **Pills press, squares inform.** Anything clickable is round-ended; anything you only read is square; dashed means not live yet.
- **The ground changes when the subject changes.** Sections are full-width blocks of paper, sand or ink, never divided by a thin line.

Live three.js vials wear the Tricolor label, drawn in code.

For laboratory research use only. Not for human or veterinary use.

## Layout

```
site3/
  src/                     the one source
    design/tokens.json     EVERY value: colours, type styles, spacing, radii, shadows, layers (the brand guide's tokens)
    design/brand-guide.md  the brand book: rules for colour, bands, interaction, layout, type, logo, label, compliance
    css/ui.css             EVERY component: grounds (.z-paper .z-sand .z-ink, bands .z-light .z-bright .z-deep),
                           buttons, links, chips, tags, cards, tiles, notices, header, panels, controls, table, ladder
    css/site.css           the shop's page layout only (hero, grids, token wheel, dashboard, footer, panels' insides)
    css/brand.css          the brand guide page's layout
    page.html              the shop (a fragment that starts at <title>; build.py wraps it)
    brand.html             the brand guide page (renders design/brand-guide.md, the palette and developer notes)
    logo-slot.svg          THE logo: <symbol id="zuma-logo">, inlined by build.py at <!-- LOGO SLOT -->
    partials/wheel.svg     the $ZUMA flywheel diagram, house colours (generated by tools/wheel.py)
    js/label.js            the Tricolor label, also reads the logo slot
    js/shop.js             data, area cards, collection, sets, lots, cart, drawer, hero switch, header, token + referral controls
    js/vials3d.js          live 3D vials (three@0.169.0)
    img/                   rendered stills (see "Images")
  build.py                 compiles tokens.json to CSS (tools/tokens2css.py), inlines ui.css + site.css, renders the guide,
                           builds dist/ and artifact/, and lints the copy
  dist/                    deployable static site: index.html, brand.html, assets/js, assets/img
  artifact/                claude.ai Artifact version: page.html (starts at <title>), brand.html, js/, img/
  tools/                   tokens2css.py, sync-ds.sh (copies tokens, brand book and ui.css into the design system),
                           render pipeline (scene.js, build.sh, all.js) and wheel.py
  test/shots.js            Playwright screenshots of dist/ at 1440 and 390, with console errors and page width
```

## Change the brand

- A colour, size, space or radius: edit `src/design/tokens.json`, then `python3 build.py`. Never write a hex code in CSS.
- A component (how buttons, cards, chips look): edit `src/css/ui.css`. Keep the rules in `src/design/brand-guide.md` true.
- A rule or wording in the guide: edit `src/design/brand-guide.md`.
- Then `sh tools/sync-ds.sh` mirrors tokens.json, the brand book and ui.css into the ZUMA design system files.

## Run locally

```sh
cd site3
python3 build.py                      # writes dist/ and artifact/, prints the compliance check
cd dist && python3 -m http.server 8080
# open http://localhost:8080
```

`build.py` needs only Python 3 (Pillow, if present, adds `og.jpg`). It fails if a never-word appears in a page or
script (the list is in the brand guide and is skipped; CSS inset syntax is ignored) and reports how often the
research-use line appears.

## Deploy

`dist/` is plain static files with relative paths. External requests: Google Fonts, three.js from
cdn.jsdelivr.net (`three@0.169.0`) and qrcodejs from cdnjs (`1.0.0`).

- **Vercel**: new project, framework preset "Other", root directory `site3`, build command `python3 build.py`
  (or none, if you commit `dist/`), output directory `dist`.
- **Netlify**: publish directory `site3/dist`, build command `cd site3 && python3 build.py`; or drag `dist/` onto the dashboard.
- **Cloudflare Pages**: build command `cd site3 && python3 build.py`, output directory `site3/dist`.

Set `og:image` to an absolute URL once the domain is known (it is relative now: `assets/img/og.jpg`).

**Artifact**: publish `artifact/page.html` with `img/*`, `js/*` and `brand.html` as supporting files. `page.html`
starts at `<title>` with no doctype/html/head/body, as the host adds them.

## Placeholders to wire before launch

Search the code for `WIRE:`.

| What | Where | Wire to |
|---|---|---|
| Checkout | `src/js/shop.js`, `#c-go` click handler | Real checkout (Shopify, WooCommerce or custom). Pass the cart, the 21+ research-use confirmation and the referral code. Keep the button disabled until the box is ticked. |
| Pay with crypto (USDC, SOL, $ZUMA) | buttons with `data-launch="crypto"` (token section and cart) | Crypto payment processor. Today they open the "Coming at launch" note. |
| Connect wallet | `data-launch="wallet"` | Wallet adapter, then the referral backend's challenge/verify. Nothing connects to a chain today. |
| Referral dashboard | `src/page.html`, `#referrals .dash` (static **example data**) | `GET /api/me/referrals` from `../zuma-referrals/` |
| Link wallet (referrals) | `data-launch="link"` | `POST /api/wallets/challenge` → sign → `POST /api/wallets/verify` |
| Request payout | `data-launch="payout"` | `POST /api/me/payouts` |
| Lot report links and QR codes | `labelData()` in `shop.js` (`zuma.example/lot/…`), "Report ↗" links in the lots table | Real report URLs; on-chain record (hash) per lot |
| Prices, sizes, lots, status | `PRODUCTS` and `SETS` in `shop.js`; Collection price in `page.html` | Catalogue |
| Member pricing, Priority tier amount | token section copy in `page.html` | Final terms after legal review |
| Referral link domain | `zuma.xyz/r/CODE` (from the spec) | Final domain |

Token copy rules: utility first; never promise price, profit, returns, yield or "number go up"; buybacks only as the
dashed "proposed, pending legal review" part of the diagram; keep the disclaimer.

## Referrals

The referral system's spec and backend live in **`../zuma-referrals/`** (`SPEC.md`; backend built separately, not
edited here). The site's `#referrals` section shows: how it works in four steps, the Level 0–5 ladder (1.0× to 3.0×,
10% to 30%, drawn to scale), a dashboard preview marked "Example data", the short rules (12-month binding, 30-day
lock, time-weighted holding, single level only, no self-referral) and the line that every referral post must keep
"For laboratory research use only. Not for human or veterinary use." and make no human-use claim. Levels and
rewards are a loyalty programme, never an investment.

## Swap the logo

1. Edit `src/logo-slot.svg`: replace the children of `<symbol id="zuma-logo">` with the final `<path>`s. Keep
   `fill="currentColor"` on the letters and `data-role="dot"` on any accent shape.
2. If the proportions change, update the symbol's `viewBox` and the `viewBox="0 0 448 100"` on each `<svg><use href="#zuma-logo"/></svg>`
   (header, footer, brand guide), plus the `.z-logo` sizes in `css/ui.css` and `css/site.css`.
3. `python3 build.py`. The 3D vial labels redraw the symbol through `ZUMA_LABEL.logo` in `js/label.js`, so they follow.
4. Re-render the stills (below) so the photographed labels match.

```sh
NODE_PATH=$(npm root -g) node site3/tools/all.js site # all stills -> site3/src/img

```

live vial still lines up with the poster it replaces.
